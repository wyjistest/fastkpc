# General input shape qualification, 2026-11-02

This campaign removes dataset-size and captured-cohort conditions from the
optional `dcc.gamma` structured/prefill/slot implementation. It keeps the model,
floating-point compiler options, exact-primary authority and strict numerical
contracts unchanged. The 351×48 input is one regression, not a dispatch key.

The work uses an authenticated local parent native and object archive. It is an
incremental development qualification, not a fresh-clone performance claim.
Real gene-expression inputs and large receipts remain local and are not shipped
with this directory. Missing inputs or CUDA cause failure, not a reported PASS.

## Tools

- `build.py TAG [PARENT_TAG]`: snapshot production sources and compile affected
  translation units with their recorded full-build numerical flags. Never installs.
- `references.py TAG CASE...`: independent CPU mgcv/native-dCov skeleton references
  using the unchanged parent native; full natural stopping (`m.max=Inf`).
- `campaign.py BUILD_TAG OUTPUT_TAG [CASE...]`: fresh R/cache, physical GPU1,
  CPUs 0–19, one BLAS thread, monitored GPU isolation. The default twelve inputs
  cover three real datasets, public synthetic 500×50, dense 500×8, sparse and dense
  structured boundaries, and a block-correlated input. All CIs and graph gates
  apply on every run. CPU-authority orientation is checked once for each of the
  three real inputs and public 500×50, outside skeleton timing.
- `supplement.py BUILD_TAG OUTPUT_TAG [PREVIOUS_TAG]`: original fresh GPU optimizer versus
  rebound slots across n=128/500, levels 3–6 and capacities 2/9/19/34/58; genuine
  original/vector-backend comparisons and execution counters; invalid leases and
  capacity rejection; public configuration tests; the three other CI methods;
  deliberately small-cache dispatch; one canonical bitwise/oracle regression.
  A previous passing job can be reused only with authenticated dependencies and
  explicit provenance. The direct slot test retains native `a0db10dc…ec2ef708`;
  the final scheduler-only correction reuses its 43 unchanged linked objects,
  records `slot-native-bridge.json`, and requalifies the changed public scheduler.
- `close.py BUILD_TAG CAMPAIGN_TAG SUPPLEMENT_TAG audit|install`: recompute every
  report and identity, optionally install the tested local binary and its linked
  objects under the native build lock. Defaults remain off. The parent binary is
  retained in its existing authenticated archive.

## Predeclared interpretation

Per-input order is **A1, C1, C2, A2, A3, C3**. A uses generic exact-primary,
coefficient reuse and retained cache/bypass/eig; C enables parameterized prefill,
structured producer, slots, work-pair and q37/q46 vector postback. Same native,
same input, alpha=.1/index=1/numCol=35, no changed statistical parameters.

Every CI and finite pMax must have absolute CPU-reference error at most `1e-10`.
Task/deletion order, adjacency, sepsets, counts, RNG, GPU authority, cache metadata
and resource closure must pass. The slot adapter additionally requires bitwise
log-SP, coefficients, fitted values and residuals, plus exact route/rank/info.

For each input separately, C/A median ≤1.05 is the declared non-regression gate;
≤.95 is the speed gate. No pooled ratio is reported. Subsecond inputs retain their
observed ratios even when noisy. Capacity/shape support is not a speed claim, and
the optimized options remain explicit because benefit depends on workload.

`campaign1` retains a reference-label fixture failure. `campaign2` retains the
fixed-log-capacity performance failure. `campaign3` retains the small-p eig-lane
guard failure. Each replacement uses a new output directory and protocol.
The first supplemental build failure (missing CUDA include directory in the
diagnostic adapter command) is retained as `supplement1`; no GPU test ran in it.
The completed slot test in `supplement2` was followed by an identity-check stop
when the not-yet-run canonical harness was corrected to check nonempty Boolean
gates. Its slot source, input driver, native and process receipt are unchanged.
Further retained attempts include a cache value below the existing 1 MiB minimum,
the real scheduler lifecycle failure after prefill capacity suspension, and a
diagnostic-runner variable-name collision before the cross-method test started.
Passing results are copied with their original command, timestamps and native
identity; they are never presented as fresh runs of a different binary.
